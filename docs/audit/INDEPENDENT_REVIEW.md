# Independent Adversarial Review

**Review date:** 2026-10-30\
**Review type:** Internal read-only reviewer pass over current source and test definitions. This is not an external security assessment or penetration test.\
**Scope:** Tenant isolation, RBAC, transaction boundaries, device telemetry, Socket.IO/outbox delivery, and changed authorization tests. No `.env`, credential, or production data was inspected. No database test or mutation was run by this reviewer.

## Executive result

This internal read-only review identified cross-tenant, transaction, and process-local realtime risks. The outbox/realtime implementation tranche and root integration tests have since corrected and tested several findings. This reviewer did not independently execute the new tests; results below are implementation-agent evidence and are not an external attestation. Endpoint/export coverage remains partial.

## Authorization and transaction evidence reviewed

- Auth middleware revalidates active membership from the database on every REST request and reconstructs permissions from the current role (`apps/api/src/middleware/auth.ts:34-61`).
- Organization IDs in reviewed route handlers are taken from `req.auth.orgId`; examples include products, batches, shipments, reports, analytics, and telemetry. Client-supplied organization IDs are not used for these REST scopes.
- Nested references in reviewed service paths are checked for organization ownership before writes: product/batch temperature profiles, batch product/supplier/storage/profile, shipment origin/vehicle/driver/batches, storage-unit warehouse, device assignment target, and incident assignee membership.
- Shipment list/detail/map, report CSV/PDF, telemetry series, audit history, and analytics queries use organization predicates in the inspected source. No bulk resource update/delete API was found in the route inventory; product deactivation is the existing delete-like action.
- Device telemetry is an intentionally separate credential-authenticated route. It uses a device key and optional HMAC; the normal API request has no user bearer session (`apps/api/src/modules/telemetry/telemetry.routes.ts:13-47`).
- A baseline of 40 MySQL integration tests was reported and passed in the prior phase. In this review turn a targeted cross-tenant run initially failed before tests because the temporary `NODE_OPTIONS` preload was omitted and `tsx` raised `uv_os_get_passwd returned ENOMEM`. The wrapped targeted run then executed 4 tests: 3 passed and 1 assertion was invalid because it expected the audit endpoint to filter on an unsupported `entityId` parameter; the implementation agent corrected the test to query supported `entityType` and compare returned entity IDs. No current passing result for that corrected test was independently observed in this review.

## Disposition after Phase 24 changes

- **IR-01 — topic permission bypass:** Corrected and tested by permission-scoped rooms; current evidence is in `realtime.test.ts` (part of the six passing outbox/realtime tests).
- **IR-02 — stale role/session on live socket:** Corrected with 30-second membership and permission revalidation and tested for role change. Revocation is periodic rather than immediate.
- **IR-03 — multi-process fanout:** Open. Socket.IO still uses its in-memory adapter. Use one realtime-serving API process or add and verify a shared adapter.
- **IR-04 — endpoint-level authorization coverage:** Improved by a five-test cross-tenant MySQL suite and route matrix; still not exhaustive for every route/export/reference.
- **IR-05 — deployment-wide DBMS metadata:** Open product/security decision.
- **IR-06 — incident rollback:** Four injected failures pass, including disposition rollback.
- **IR-07 — shipment rollback:** Dispatch and creation rollback on outbox insertion failure pass; cancellation/release rollback remains open.
- **IR-08 — telemetry rollback:** Outbox insertion failure rolls reading, device freshness and audit back; retrying the same sequence succeeds.

## Review limitations and disposition

- This reviewer did not run a penetration test, browser suite, database mutation, or independent external service review.
- GitHub Actions, Docker, production TLS/networking, and multi-replica delivery were not exercised.
- Source-level inspection and selected tests do not establish a complete endpoint authorization guarantee. The route matrix, transaction failure tests, socket permission/revocation tests, and two-server delivery test remain required evidence.
- The realtime implementation agent was notified of IR-01 through IR-03. Findings remain open until the resulting tests and implementation are reviewed and pass.
